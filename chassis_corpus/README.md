# CHASSIS Scenario Author — стартовый синтетический корпус

**48 русскоязычных запросов / 36 независимых семантических групп**. Это стартовый демонстрационный корпус для EDA, разработки формата DSL, сборки few-shot промптов и проверки экспериментального пайплайна.

## Содержимое

- `data/scenarios.jsonl` — полный корпус; по одной JSON-записи на строку
- `data/few_shot_pool.jsonl` — 32 записи (22 независимых сценария) для демонстраций в промпте.
- `data/dev.jsonl` — 8 записей (7 сценариев) для подбора конфигурации.
- `data/test.jsonl` — 8 записей (7 сценариев) для независимой проверки; итоговую метрику качества продукта на синтетическом `test` выдавать нельзя.

## Структура записи

- `request_id`, `scenario_group_id`, `paraphrase_group_id`: уникальный запрос и общая группа смысловых перефразировок.
- `text`: фраза пользователя.
- `reference_dsl`: предполагаемое преобразование в DSL `0.1-draft`.
- `scenario_class`, `complexity`, `language`, `split`, `source_type`: метаданные для EDA и разбивки.
- `annotation_status`: у всех `needs_expert_review`.
- `review_notes`: проблемные места схемы/конкретного примера.

## Принципы черновой DSL

`operation: add`; `actors` — массив акторов с `id`, `type`, опциональными `maneuver`, `speed_mps: [min,max]`, `placement`, `trigger`, `state`, `role`. Привязка задаётся **семантически**, через `placement.anchor` / `placement.relation`, без координат. Триггеры относятся к семантическим условиям, без генерации траекторий. Допустимые значения `anchor`, `relation`, `maneuver`, `trigger.type` в этой версии являются **черновым словарём**, который нужно согласовать с разработчиками DSL и модулями привязки к карте.

Поля `assumptions` и `provenance` оставлены пустыми. **Это не означает, что допущений нет**: согласованная span-level разметка ещё не выполнена. Не оценивать метрики качества этих полей до завершения разметки.

`speed_mps` сохраняет явно заданную численную скорость из запроса (например, 5 м/с) без автоматического изменения. Для проверки физической допустимости нужны отдельные экспертные правила.
